# mini_basic Development Pipeline & LLM/Autonomous Agent Guide

This document describes the status implementation, TODO/job pipeline, how autonomous work happens without user interaction, what requires user final approval, and how to continue work (task-by-task or fully autonomously) as an LLM or script.

It is intended for any LLM, agent, or developer to pick up and continue correctly.

## 1. Status Implementation Overview

The status system is designed for monitoring (especially phone/tablet via OneDrive sync) and autonomous agent coordination.

Core components:

- **status.html** (generated): Main dashboard. Auto-refreshes every 60s. Shows:
  - Currently Working On (program + focus from CURRENT_TASK or override)
  - TODOs for this program
  - Workload / resource status (from agent_resource)
  - Debugging step (from DEBUG_STEP.txt)
  - User Final Approval Checklist (from USER_APPROVAL.txt / AGENT)
  - Confirmed Working / Pending
  - Recent Work Log
  - Issues
  - Alive/heartbeat counters

- **Generated by**:
  - `utils/status_updater.py:StatusUpdater.update(...)` — builds clean HTML. Supports direct fields or heartbeat.
  - `test/progress_runner.py`:
    - `update_project_status(**overrides)` — auto-fills from project files (FEATURES_DONE for TODOs, CURRENT_TASK, _run_progress.log, CORPUS_AUDIT, etc.), then calls StatusUpdater.
    - `write_phone_summary(heartbeat=True/False)` — produces compact PHONE_PROGRESS.txt, SYNC_STAMP.txt, status.html updates, RSS if needed.
    - Helpers: `_load_todo_items()` (from FEATURES_DONE.txt lines starting `-- `), `_load_current_task_line()`, `_last_test_run_info()`, corpus audit summary, etc.

- **Source-of-truth .txt files** (human + LLM; agents write these):
  - `CURRENT_TASK.txt`: What the agent is actively working on (free-form, updated on real work).
  - `FEATURES_DONE.txt`: Changelog. Lines `OK ...` = done. Lines `-- ...` = TODO (parsed as dashboard TODOs).
  - `CORPUS_AUDIT.txt`, `DEBUG_STEP.txt`, `USER_APPROVAL*.txt`, `WORK_LOG.txt`, `COMPARE_REPORT.txt`, etc.
  - `AGENT_POLICY.txt`: Rules the agent/LLM **must** follow.
  - `AGENT_RESOURCE_ALERT.txt`, `RESOURCE_CHECK.txt`: Resource guards.

- **status.html is derived** (do not hand-edit for progress):
  - Built by `utils/status_updater.py` via `test/progress_runner.update_project_status()`.
  - **Poll-on-change** (primary): `utils/status_sources.py` fingerprints the .txt sources;
    `scripts/progress_heartbeat.py` rebuilds status.html **only when fingerprints change**.
  - Stamp file: `.status_sources_stamp.json` (last seen fingerprints).
  - **Agent-staleness check** (less frequent, default every ~30 min if sources unchanged):
    if CURRENT_TASK / FEATURES_DONE / etc. have not been touched for 6h, rebuild once
    with a dashboard issue so monitors notice idle agents.
  - Scheduled task: `scripts/ps1/register_progress_task.ps1` → every **5 minutes**,
    `pythonw scripts/progress_heartbeat.py --quiet` (exits immediately; no daemon).

- **Update flow (autonomous)**:
  1. Agent finishes a step → writes/updates CURRENT_TASK.txt, FEATURES_DONE.txt, etc.
  2. Next poll (or `python scripts/progress_heartbeat.py`) sees fingerprint change → full `update_project_status()`.
  3. Optional immediate rebuild after big edits: `update_project_status(...)` or `progress_heartbeat.py --force`.
  4. Resource checks: `python scripts/verify_resources.py`
     (includes Grok/agent leftover Python scan — AGENT_POLICY §5b).
     Orphans: `python scripts/probe_agent_python.py` / `--kill-orphans`.

No long-running daemons except the Windows scheduled task (fire-and-forget every 5 minutes).

## 2. Pipeline of Jobs from TODO (Autonomous Flow)

TODOs originate primarily from:

- `FEATURES_DONE.txt` lines beginning with `-- ` (e.g. `-- corpus runnable audit...`).
- `CURRENT_TASK.txt` (free text "in progress ..." + bullet details).
- `CORPUS_AUDIT.txt` FAIL entries.
- `USER_APPROVAL.txt` `[ ]` entries.
- Hard-coded priority in `AGENT_POLICY.txt` (update as needed).

**Autonomous / no-user-interaction pipeline** (LLM/agent/script can run this loop):

**MUST follow AGENT_POLICY §3b (BEGIN/END status script) and §6b (user interrupt) on every job.**

1. **BEGIN job** (mandatory — see AGENT_POLICY §3b):
   - Read AGENT_POLICY, CURRENT_TASK, FEATURES_DONE (`--` todos), USER_APPROVAL*, CORPUS_AUDIT, WORK_LOG, resources.
   - Set `CURRENT_TASK.txt` Focus line to the single program/task (never leave Program: None while working).
   - Open session todos; `log_work_event('BEGIN …')` + `update_project_status()`.

2. **Determine single focus** (Single Focus Rule — never agent-code two programs at once):
   - **User-raised issues always go first** (AGENT_POLICY §2a) — bug reports, feature
     requests in chat, redirects. Park the standing queue; do not ask “what next?”.
   - Then: land uncommitted product work → finish active CURRENT_TASK → FEATURES_DONE
     `--` / continuation plan → deferred.
   - User may *playtest* other ready programs in parallel; agent does not code them in parallel.

3. **Do work autonomously** (check user input at midpoints — §6b):
   - Use `verify_*.py` / `verify_program.py <name>` for agent-only snippet checks.
   - Targeted pytest / probes with `display='none'` / dummy SDL in autonomous mode.
   - Edit, re-test; `verify_resources.py` before/after heavy work.
   - Never claim "all pass" — only per-item after individual confirmation.

4. **END job** (mandatory — §3b):
   - **Tick out** finished todos (`completed`; FEATURES_DONE `--` → `OK`).
   - Update USER_APPROVAL* / CORPUS_AUDIT if readiness changed.
   - `log_work_event('END …')` + `update_project_status()`.
   - Commit on feature branch when code changed.

5. **User gate (only for final approval)**:
   - Ready programs: `[ ]` in USER_APPROVAL + `OK` in USER_APPROVAL_AGENT.
   - **User** runs the program, confirms in chat; agent then marks `[x]`.
   - Never auto-approve whole programs.

6. **Loop / next**:
   - Refresh state; if waiting on user, Focus names the ready program or "waiting on user: …".
   - Heartbeat keeps the dashboard live when idle.

User chat always preempts agentic work (§6b): handle interrupt, update status, then resume.

## 4. How to Continue Work (Task-by-Task or Autonomously) as LLM

**Startup checklist for any LLM/agent (read these first):**
1. AGENT_POLICY.txt (core rules — single focus, resource awareness, user approves whole programs only, **pygame/display safety + no leftover windows (section 8)**, etc.)
2. CURRENT_TASK.txt
3. FEATURES_DONE.txt (scan for -- TODOs)
4. STATUS.txt / PROGRESS.txt + status.html
5. USER_APPROVAL.txt + USER_APPROVAL_AGENT.txt + CORPUS_AUDIT.txt
6. This DEVELOPMENT_PIPELINE_AND_LLM_GUIDE.md

**Pygame rule reminder:** In autonomous mode always `display='none'` / `SDL_VIDEODRIVER=dummy` + force `ensure_no_pygame_leftovers()`. Real windows only via user-cooperative runs (user executes the command and reports). See AGENT_POLICY section 8.

**Autonomous loop (no user needed until final approval):**
```bash
# Typical session
cd mini_basic
python scripts/verify_resources.py          # before heavy work (+ agent-python scan)
python scripts/probe_agent_python.py        # list hung Grok/agent Python leftovers
# python scripts/probe_agent_python.py --kill-orphans
# ... do work on current focus (one program) ...
python test/verify_XXX_step.py              # agent snippets
python -m pytest -q -m "phase1 and not slow" --timeout=20   # safe regression
python -m unittest test.test_bbc_dialect_sdl -v   # targeted
python scripts/compare_bbc_outputs.py ...
python test/corpus_audit_probe.py ...
# Record
python -c "
from test.progress_runner import update_project_status
update_project_status(
    current_program='wheel.txt',
    focus='CIRCLEFILL variations + audit',
    todos=['Fix remaining errors', 'Re-audit']
)
"
# For program ready for user:
python -c "
from utils.user_approval import write_agent_results
write_agent_results(['OK wheel.txt :: all 2 snippet checks passed'])
"
# Then wait for user confirmation before marking [x] in USER_APPROVAL.txt
```

**Task-by-task mode:**
- Pick one -- item or CURRENT_TASK bullet.
- Work only on it until agent-verified + (for programs) user final OK.
- Update DEBUG_STEP.txt while deep in one step.
- Use `python run_program.py <name>` (prints user cmd) when ready for user.

**Key scripts for autonomous work:**
- `scripts/verify_resources.py`, `scripts/probe_agent_python.py`, `utils/agent_resource.py`
  (AGENT_POLICY §5b — regular probe for leftover Grok/agent Python processes)
- `test/run_regression.py`, `test/verify_*_step.py`, `verify_program.py`
- `scripts/compare_bbc_outputs.py`, `test/corpus_audit_probe.py`
- `test/progress_runner.py:update_project_status(...)`
- `utils/user_approval.py` + `user_approval.py` helpers
- `scripts/run_corpus_menu.py`, `run_program.py` (for guidance)

**Never:**
- Work on >1 program.
- Run massive parallel suites.
- Claim full corpus done without per-program user confirmation.
- Bypass user final check for programs.

Update this guide and AGENT_POLICY when priorities or pipeline change.

## 5. Text-Based Development Installation

The end-user install (see `Programming/install.ps1` + `mini_basic_text_part0*.txt`) is pure-PowerShell, self-contained reconstruction from text archives (BEGIN/END FILE markers). It produces the minimal runnable tree + sets up launchers + MINIBASIC_DIR.

For **development**, we need the full tree including extras we previously copied from the complete source:

**Core (end-user files, reconstructed by the 3 text parts):**
- mini_basic/ (package)
- basics/
- mini_basic.py, mb.py, bbc_*.py, display.py
- documentation/ (partial), tools/, requirements-*.txt, README.md, FEATURES_DONE.txt, etc.

**Dev extras (added on top — the files chosen/copied):**
- All status/agent/tracking: AGENT_POLICY.txt, AGENT_RESOURCE_ALERT.txt, CURRENT_TASK.txt, STATUS.txt, PROGRESS.txt, WORK_LOG.txt, FOLLOW_PROGRESS.txt, CORPUS_AUDIT.txt, COMPARE_REPORT.txt, DEBUG_STEP.txt, FEATURES_DONE.txt (full), RESOURCE_CHECK.txt, USER_APPROVAL*.txt, USER_VERIFY_SNIPPETS.txt
- examples/ (full corpus of programs)
- test/ (full, including probes, corpus/, manual/, run_regression.py, etc.)
- scripts/ (full runners, heartbeat, compare, verify, ps1/ scheduled task helpers)
- lib/ (BBC libraries, fonts)
- utils/ (status_updater, user_approval, agent_resource, program_run_guide, debug_step)
- Full documentation/ (feature_matrices/, FEATURE_TESTS_FOR_USER.txt, etc.)
- Other supporting: .ps1 helpers if present, etc.

### How to set up a dev tree (text-based like end-user + builder option)

**Option 1: Pure text-based (like end-user, no Python needed for setup)**

Use `dev_install.ps1` (see below) + core 3 text parts + additional dev text parts (generated from the extras).

Place in a folder:
- install.ps1 or dev_install.ps1
- mini_basic_text_part01.txt ... (core)
- dev_text_part01.txt, dev_text_part02.txt ... (extras: status files + examples + test selected + scripts + lib + utils + docs)

Run: `.\dev_install.ps1`

It will reconstruct core into `mini_basic\`, then overlay dev extras.

**Option 2: Builder script (Python, recommended for dev)**

```powershell
# After placing the text parts
python tools/reconstruct_from_text.py mini_basic_text_part*.txt dev_text_part*.txt --output mini_basic_dev/
# or use a dedicated builder
python build_dev_tree.py --parts "mini_basic_text_part*.txt" "dev_text_part*.txt" --output .
```

This uses the robust Python parser (handles escaping, BOM, etc.) and is easier to extend for dev files.

### Generated / Recommended Dev Text Parts Strategy

Use `tools/create_text_archive.py` (adapted) or equivalent to split the dev extras into text parts (same BEGIN/END format as core).

Core parts stay the 3 minimal ones.

Dev extras can be one or more `dev_text_partNN.txt` containing only the added files/dirs.

The dev_install.ps1 (or builder) concatenates and reconstructs everything into the target, preferring dev files for overlaps (e.g. FEATURES_DONE.txt).

### dev_install.ps1 (to be placed alongside the parts, modeled on end-user install.ps1)

(See the created file in the tree.)

It supports:
- Same PS reconstruction for core + dev parts.
- `-UsePythonBuilder` or auto-detect Python → use `python tools/reconstruct_from_text.py ...`
- `-TargetDir`
- Uninstall support.
- Sets up for dev (perhaps additional launchers or env for tests).

After install, the target will have the full dev tree ready for LLM/agent work, tests, status pipeline, etc.

Run the register task for heartbeat:
`powershell -File scripts/ps1/register_progress_task.ps1`

Then the autonomous pipeline (heartbeat + agent work) is live.

This allows reproducible text-based distribution of the full development setup (core + the exact extras chosen for LLM/agent context: full examples, test harness, scripts, status tracking, lib, utils, etc.).
