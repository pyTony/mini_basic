# AGENT_POLICY.txt
# Core rules that LLM / autonomous agents MUST follow on every session.

## 1. Mandatory Startup Checklist (read this every time)
- Read AGENT_POLICY.txt (this file) — **pay special attention to section 8 (Pygame safety / no leftover windows)** and **§5b (Grok Python leftovers)**
- Read CURRENT_TASK.txt
- Read FEATURES_DONE.txt (especially lines starting with -- )
- Read DEVELOPMENT_PIPELINE_AND_LLM_GUIDE.md (at least the pipeline section)
- Read DEVELOPMENT_GIT_USAGE.md
- Run: python scripts/verify_resources.py
  (includes agent-python leftover scan; or: `python scripts/probe_agent_python.py`)
- If orphan agent Python shows up: kill clear orphans
  (`python scripts/probe_agent_python.py --kill-orphans`) unless the user is
  deliberately running that command.
- If any prior pygame state is suspected: explicitly call `from mini_basic.display import ensure_no_pygame_leftovers; ensure_no_pygame_leftovers()` early.

## 2. Single Focus Rule (HIGHEST PRIORITY)
- Work on **exactly one** task / program / focus at a time.
- Never touch another program until the current one has explicit user approval.

### 2a. Queue priority (always — do not invent another order)
**User-raised issues are always next.** Anything the user reports, requests, or redirects
to in chat preempts the standing autonomous queue.

Priority order when choosing work (first match wins):

1. **User issue / request** (this chat or still open in CURRENT_TASK as user-driven)
   - Bug report, “it crashes”, “could you add…”, UX complaint, doc gap they asked for,
     “also do X”, mid-session redirect — **top of queue immediately**.
   - Park autonomous Job N: note it under CURRENT_TASK “Parked: …”, do **not** continue
     Job N until the user issue is done or the user explicitly says resume the queue.
2. **Uncommitted product work** from the interrupted/prior focus (land or finish safely).
3. **Active CURRENT_TASK Focus** if still unfinished and *not* superseded by (1).
4. **Standing autonomous queue** — FEATURES_DONE `--` lines / continuation plan Jobs
   (PRINT arrays, Phase 2b, phase2 markers, 1.00 ship prep, …).
5. **Deferred / optional** only when higher slots are empty.

Identify focus from (in that spirit):
  - Latest user message and open user-driven lines in CURRENT_TASK.txt
  - FEATURES_DONE.txt lines starting with "--" (especially `-- USER: …` if used)
  - CORPUS_AUDIT.txt or USER_APPROVAL*.txt

Recording user issues (so the next session still picks them first):
  - Set CURRENT_TASK Focus to the user issue **before** other work.
  - Prefer a FEATURES_DONE line `-- USER: <short issue>` until fixed → `OK USER: …`.
  - Never ask “what next?” while any user issue is open.

## 3. Status & Communication
- **Source of truth = project .txt files**, not status.html:
  - CURRENT_TASK.txt (active focus)
  - FEATURES_DONE.txt (`OK …` done, `-- …` TODO)
  - CORPUS_AUDIT.txt, USER_APPROVAL*.txt, DEBUG_STEP.txt, WORK_LOG.txt, etc.
- After meaningful work: **update those .txt files**. That is required.
- **status.html is generated** by polling those files:
  - Scheduled: `scripts/progress_heartbeat.py` (via register_progress_task.ps1)
    rebuilds status.html **only when source fingerprints change**.
  - Optional immediate rebuild: `python -c "from test.progress_runner import update_project_status; update_project_status()"`
    or `python scripts/progress_heartbeat.py --force`
- Do **not** rely on a frequent empty "heartbeat rewrite" of status.html.
  Heartbeat is light: poll .txt change + rare check that agents still touch
  CURRENT_TASK / FEATURES_DONE (staleness warning if idle too long).
- Only use status.html for progress *display* (phone/OneDrive).
- Never use phone summaries, RSS, or other channels (they have been removed).

## 3b. MUST-FOLLOW: Agentic Job Status Script (BEGIN + END)
Every agentic **job** (a coherent focus unit: one program fix, one approval batch
handler, one probe+patch cycle) **must** run status bookkeeping at **start and end**.
Skipping either end is a policy violation.

### BEGIN job (before first code edit or long probe)
1. Read `CURRENT_TASK.txt`, `FEATURES_DONE.txt` (`--` todos), `USER_APPROVAL*.txt`,
   `AGENT_RESOURCE_ALERT.txt` / `python scripts/verify_resources.py`.
2. Set **single focus** in `CURRENT_TASK.txt` first line:
   `Focus: <program-or-task> — <one-line goal>`
   so status "Currently Working On" is never stale `None` unless truly idle.
3. Create/update in-session todos (todo tool or FEATURES_DONE `--` lines) for the job.
4. Log start:  
   `python -c "from test.progress_runner import log_work_event, update_project_status; log_work_event('BEGIN <focus>: <goal>', kind='WORK'); update_project_status()"`
5. Only then start probes/edits.

### DURING job (midpoints)
- After each meaningful probe/fix/commit: check user input queue (see §6b).
- **Probe Grok/agent Python leftovers** (see §5b) after long probes, background
  tasks, or any job that used `python -c` / `_probe_*.py` — at least every
  ~30–60 minutes of agent work, and immediately if the machine feels thrashy.
- Optionally `log_work_event` for milestones; keep CURRENT_TASK focus accurate.

### END job (before stopping or switching focus)
1. **Tick out todos** that are actually done:
   - Session todo tool → `completed` (not left `in_progress`/`pending` if finished).
   - FEATURES_DONE: move `-- item` → `OK item` when the item is done; leave `--` only for remaining work.
2. Update `CURRENT_TASK.txt`: either next focus, or idle note if waiting on user.
3. Update approval/corpus files if the job changed readiness (`USER_APPROVAL*`, `CORPUS_AUDIT`).
4. **Kill leftover agent Python** from this job: background `python -c` probes,
   `test/_probe_*.py`, hung CASE/ON ERROR experiments. Do **not** kill the user's
   intentional `mini_basic.py … saucer.bbc` (etc.) demos. Prefer:
   `python scripts/probe_agent_python.py` then `--kill-orphans` if orphans listed.
5. Log end + rebuild status:  
   `python -c "from test.progress_runner import log_work_event, update_project_status; log_work_event('END <focus>: <result>', kind='WORK'); update_project_status()"`
6. **Git gate (required — continuous history):**
   - Run `git status -sb` (and `git diff --stat` if anything is dirty).
   - If this job changed **code, tests, packaging, or durable docs** (including
     FEATURES_DONE / CORPUS_* / docs/SESSION_* when recording handoffs):
     - Stay on a **focus branch** (never commit straight to `master`).
     - Stage **explicit paths** (not blind `git add -A` if junk is present).
     - **Commit** with a clear message referencing the focus.
   - If dirty only with accidental noise (probes, logs): discard or leave untracked;
     do not commit probes/`*.prof`/debug dumps.
   - If you intentionally skip commit: one WORK_LOG line  
     `NO-COMMIT <reason>` (e.g. user said wait / local experiment only).
   - Never leave intentional deletes of packaging/docs (`LICENSE`, `MANIFEST.in`,
     `docs/PACKAGING.md`, manuals) without user request — `git restore` them.

### Idle / waiting on user
- If the only remaining work is user playtesting ready `[ ]` programs: set focus to the
  first ready program name (or explicit "waiting on user: saucer") so Program is not `None`.
- Do **not** leave todos marked in_progress when the agent has stopped.

## 4. Git Workflow (for all code changes)
- Never commit directly to master.
- Always work on a dedicated branch: `git checkout -b fix/your-focus` (or continue the
  existing focus branch if still open).
- **Commit at every END job** that produced durable changes (see §3b step 6). Status
  `.txt` bookkeeping without a commit is incomplete for continuous git use.
- Prefer small, frequent commits with clear messages referencing the focus.
- Merge to master only after user has explicitly approved the whole program.
- Use git diff / git show / git log for history instead of loading full old files (light footprint).
- Main-file coverage checklist when staging:
  - `mini_basic/**` package code touched by the job
  - matching `test/test_*.py` (not `_probe_*`)
  - `FEATURES_DONE.txt` / `CURRENT_TASK.txt` / `WORK_LOG.txt` as updated
  - `CORPUS_*` / `USER_APPROVAL*` if readiness changed
  - `docs/` / packaging (`pyproject.toml`, `LICENSE`, `MANIFEST.in`) if changed

## 5. Resource Awareness & Light Footprint
- Always run python scripts/verify_resources.py before and after heavy work.
- Prefer git diffs, versions, and small context over loading entire files.
- Call gc.collect() when appropriate.
- Keep memory/CPU usage low during repeated agent sessions.

## 5b. MUST-FOLLOW: Probe Grok/agent leftover Python processes
Hung agent probes (background `python -c`, `test/_probe_*.py`, incomplete
CASE/ON ERROR experiments) have burned **hours of CPU** and thrash the machine.
Treating this as optional is a policy violation.

### When to probe (regular cadence)
1. **Startup** (checklist §1) — with `verify_resources.py` or
   `python scripts/probe_agent_python.py`.
2. **During long jobs** — at midpoints and at least every ~30–60 minutes of
   continuous agent work; always after a backgrounded/timed-out shell command.
3. **END job** — before declaring the job done (§3b).
4. **After user reports** high CPU, fans, or “something still running”.
5. **Before starting another heavy probe** — do not stack zombies.

### What counts as agent/Grok-related
- `test/_probe_*.py`, `_run_one_probe.py`, `corpus_audit_probe.py`
- `python -c` snippets importing `BASICInterpreter` / `InterpreterConfig`
- Long-lived agent experiments under the mini_basic tree (e.g. `t_saucer*.py`)
- Session tooling that is clearly automation, not a user demo window

### What NOT to kill without asking
- User demo: `python mini_basic.py … examples/…` or corpus files the user launched
- Active `pytest` the agent or user just started
- This probe script / `verify_resources.py` itself

### Commands
```
python scripts/probe_agent_python.py              # list agent-related + orphans
python scripts/probe_agent_python.py --kill-orphans  # kill clear orphans only
python scripts/verify_resources.py                # memory check + short python scan
python scripts/verify_resources.py --kill-orphans
```

### Background / timeout rule
- Prefer **timeouts** on exploratory `python -c` probes (or short programs with END).
- If a shell task is backgrounded or exceeds default timeout: **track the PID/task**,
  and on completion/kill/timeout **verify it is gone** with `probe_agent_python.py`.
- Never leave multi-hour `python -c` ON ERROR / CASE experiments running.

### Log
- If orphans were killed: one WORK_LOG line, e.g.
  `agent-python: killed orphan pids … (hung probe)`.

## 6. User Approval Gate
- Only the user can finally approve a whole program.
- After fixes: ask user to run and confirm.
- Update USER_APPROVAL*.txt and FEATURES_DONE.txt only after real user confirmation.
- Maintain three lists in USER_APPROVAL.txt:
  - `[x]` user-approved
  - `[ ]` ready for user OK (agent found no blocking errors)
  - comments for agent-blocked programs (not ready)

## 6b. User Interaction During Agentic Work (INTERRUPT POLICY)
User chat **always preempts** long autonomous runs. This is not optional.

### When a user message arrives mid-agentic work
1. **Stop** the current autonomous step at the next safe boundary (end of probe, end of one fix, end of one commit). Do not start a new heavy job until the user is handled.
2. **Read and answer** the user message first (approval, bug report, screenshot, question).
3. **Record** outcomes immediately:
   - Approvals → `USER_APPROVAL.txt` + `USER_APPROVAL_AGENT.txt` + `WORK_LOG.txt`
   - Bug reports → fix or note in `CURRENT_TASK.txt` / `FEATURES_DONE.txt`
4. **Refresh status**: update `CURRENT_TASK.txt` focus if needed; regenerate `status.html` so "Currently Working On" is not stale `None`.
5. **Resume** agentic TODO only after the interrupt is handled:
   - If the user raised a new issue or redirected: that issue is **queue top** (§2a);
     park the previous autonomous focus until the user issue is closed.
   - Prefer returning to the interrupted focus only when the user did **not** redirect.
   - If the user approved a ready program, do not reopen it; pick next agent-blocked item
     (still after any open user issues).
6. **Do not** treat user testing of *ready* programs as a conflict with single-focus agent work on a *different* blocked program (e.g. user tests saucer while agent works piechart). Parallel user-play is allowed; parallel *agent* coding on two programs is not.

### Workload when interrupted
- After user interrupt: re-check `scripts/verify_resources.py` / `AGENT_RESOURCE_ALERT.txt` before restarting heavy probes.
- Re-run **§5b** Python leftover probe (kill orphans if present).
- Prefer one small resume step over restarting a full corpus audit.
- Log a short `WORK_LOG` line: `USER interrupt handled; resume <focus>`.

### Queue check habit
- At natural midpoints of agentic work (after each probe, fix, or commit), **check for new user input** before continuing the next step.
- Never assume silence means "keep burning resources" without updating status.
- Same midpoints: glance at agent-python leftovers when any background probe was used.

## 8. Pygame / Display Window Safety (Especially No Leftover Windows)
**HIGHEST PRIORITY in autonomous mode.**

- **Autonomous operating mode** (LLM/agent sessions, scheduled heartbeat with pythonw.exe, `test/progress_runner.py`, `corpus_audit_probe.py`, any non-interactive / background run, resource-constrained work):
  - **Strictly avoid all automatic pygame tests and real window creation.**
  - Always construct with `InterpreterConfig(display='none', display_locked=True)` (or equivalent) or set `os.environ.setdefault('SDL_VIDEODRIVER', 'dummy')` **before** importing pygame or creating BASICInterpreter.
  - Never set `hold_display_open=True`.
  - After **every** execution (success, error, timeout, KeyboardInterrupt), ensure `mini_basic.display.ensure_no_pygame_leftovers()` is called (via `_shutdown_display` or directly).
  - **Especially ensure no left over pygame windows.** A stray SDL window from a previous/crashed autonomous run is a failure. Force cleanup + gc.collect(). If any pygame state remains, treat as resource violation.
  - Heartbeat/scheduled tasks must continue using `SDL_VIDEODRIVER=dummy`.

- **Cooperative / user-present mode** (user is actively chatting and directing, not pure autonomous agent loop):
  - Do **not** auto-spawn pygame windows from the agent.
  - Guide the *user* to run the command themselves when visual inspection is needed:
    `python mini_basic.py --pygame examples/graphics/wheel.txt`
    (or the exact command printed by `scripts/run_program.py`).
  - User observes, interacts with, and closes the window, then reports results back.
  - Only after explicit user confirmation may graphics behavior be considered verified.
  - Agent may still use internal capture (e.g. `capture_framebuffer`) for automated checks without a window.

- In all modes: prefer internal state inspection and `display='none'` tests. Real pygame windows are only for final user-cooperative verification of BBC graphics fidelity.
- Always call `python scripts/verify_resources.py` before/after any display-related or heavy work.
- Update stuck_tests.txt, test markers, and Phase guidance when changing what runs automatically.

See:
- DEVELOPMENT_PIPELINE_AND_LLM_GUIDE.md (full autonomous loop)
- docs/git/INDEPENDENT_FIXES.md
- GIT_QUICKSTART.md
- test/README.txt (Phase 1 non-gfx vs Phase 2 graphics isolation)
- `mini_basic/display.py:ensure_no_pygame_leftovers`

Violating these (especially single focus or skipping user approval) is not allowed.
